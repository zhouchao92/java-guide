# 三、RAG 知识层

本文是学习路线的阶段三（第 4 周）：掌握 RAG（Retrieval-Augmented Generation）全链路，从文档解析到评估闭环。RAG 是企业 Agent 最常见的落地形态——让模型基于**你私有的、可更新的**知识作答。


## 一、RAG 全链路

```
离线（索引管道）：
  文档解析 → 清洗 → 分块(Chunking) → Embedding → 写入向量库

在线（查询管道）：
  用户提问 → 查询改写/扩展 → 混合检索(向量+关键词) → Rerank 重排
           → 截取 Top-K 组装上下文 → LLM 生成（带引用） → 评估
```

两侧独立演进：**索引质量决定上限，检索质量决定大头，生成只是临门一脚**。


## 二、离线索引管道

### 2.1 文档解析

| 源格式        | 方案                                      | 注意点               |
|---------------|-------------------------------------------|----------------------|
| PDF（文本型） | Apache PDFBox / pdfplumber / Unstructured | 扫描件需先 OCR       |
| Office        | Apache POI（Java）、mammoth               | 表格是难点           |
| Markdown/HTML | 去标签保结构                              | 标题层级用于分块     |
| 代码          | AST 或按函数分块                          | 保留文件路径作元数据 |
| 数据库/工单   | 结构化抽取                                | 走字段映射而非切块   |

解析产物必须**保留结构信息**（标题路径、页码、表格边界），它决定后续分块与引用溯源的质量。

### 2.2 分块策略（Chunking）

| 策略           | 适用               | 要点                                   |
|----------------|--------------------|----------------------------------------|
| 固定长度切分   | 通用兜底           | 512~1024 token + 10%~20% 重叠          |
| 结构感知       | Markdown/代码/文档 | 按标题/函数/章节切，天然对齐语义       |
| 语义分块       | 长文精读           | 按 embedding 相似度突变处切            |
| 父子/小→大检索 | 精准定位           | 小块用于匹配，命中后回传父级大块给 LLM |

每个 chunk 要携带**元数据**：来源文档、章节路径、更新时间、权限标签（企业级必备，检索时按权限过滤）。


## 三、Embedding 与向量库

### 3.1 Embedding 要点

- 把文本映射为定长向量，语义相近 → 向量相近（余弦相似度）。
- **中英混杂语料**选多语言模型；选型以公开 benchmark（如 MTEB/C-MTEB）+ **自己的评估集**为准。
- 索引与查询必须用**同一个 embedding 模型**，换模型 = 全量重建索引。
- 归一化、维度、最大输入长度是接入时必查参数。

### 3.2 向量库选型（企业 Java 栈）

| 方案                         | 优势                                  | 劣势                   | 适合                |
|------------------------------|---------------------------------------|------------------------|---------------------|
| **pgvector**（PostgreSQL）   | 与业务库同库、事务/权限复用、运维简单 | 超大规模性能弱于专业库 | 中小规模、已在用 PG |
| **Elasticsearch/OpenSearch** | 全文+向量混合检索原生支持、生态成熟   | 资源占用大             | 已有 ES 的企业      |
| **Milvus**                   | 专业向量库、亿级规模、云原生          | 独立运维成本           | 大规模、高并发      |
| Redis Vector                 | 低延迟、复用缓存设施                  | 复杂检索能力弱         | 热数据缓存场景      |

选型口诀：**能用现有基础设施就别引入新组件**；规模上来再迁专业库。


## 四、在线查询管道

### 4.1 混合检索 + Rerank

1. **查询改写**：补全指代（"它昨天为什么挂了" → 补主语）、拆多问题、生成假设性文档（HyDE）。
2. **混合检索**：向量语义检索（召回同义表达）+ BM25 关键词检索（抓住专有名词/型号/错误码），结果融合（RRF）。
3. **Rerank 重排**：用 cross-encoder 模型（bge-reranker 等）对 Top-50~100 精排，取 Top-4~8。**rerank 是性价比最高的效果提升项**。
4. **组装上下文**：按相关度排序，附来源标注，控制总 token 预算。

### 4.2 进阶：Graph RAG

实体关系密集的场景（故障传播链、组织架构、变更影响面），先构建知识图谱，再"图谱关系 + 向量检索"双路召回。成本高，**仅在纯向量检索明显不够时引入**。


## 五、RAG 评估（没有评估 = 无法上生产）

### 5.1 指标分层

| 层次   | 指标                   | 含义                           |
|--------|------------------------|--------------------------------|
| 检索侧 | Recall@K、MRR、NDCG    | 相关文档有没有被捞回来         |
| 生成侧 | Faithfulness（忠实度） | 答案是否忠于检索内容（防幻觉） |
| 生成侧 | Answer Relevancy       | 答案是否切题                   |
| 端到端 | 引用准确率、人工评分   | 引用的出处是否真支持该句       |

### 5.2 评估集搭建

1. 收集 **50~200 条真实问答对**（工单、客服记录、用户提问）作为 golden dataset；
2. 为每条标注**标准答案与出处**；
3. 用 RAGAS 等框架自动化：`context_precision / context_recall / faithfulness / answer_relevancy`；
4. **每次改动跑一遍**：换分块、换 embedding、调 Top-K 都要有回归数字，而非"感觉好了"。

### 5.3 常见故障定位

| 症状             | 大概率原因               | 排查方向                         |
|------------------|--------------------------|----------------------------------|
| 答非所问         | 检索没捞到               | 看 recall，查分块/改写           |
| 有相关内容仍答错 | 组装差/被干扰            | 看排序、去重、预算               |
| 一本正经胡说     | 未强制引用、模型自由发挥 | 要求逐句引用 + faithfulness 检查 |
| 漏答多问         | 查询未拆分               | 问题分解、多路召回               |
| 引用不存在       | 幻觉引用                 | 强制从候选块 ID 中选             |


## 六、学习资源（阶段三）

### 必读（按顺序）

1. **LangChain 官方文档《RAG》概念章节**——https://python.langchain.com/docs/tutorials/rag/ （链路全景最清晰的免费教程，语言是 Python 但概念通用）。
2. **Pinecone 官方 Learning Center《Retrieval-Augmented Generation》**——https://www.pinecone.io/learn/ 系列文章（分块、混合检索、评估各有专篇，工程视角扎实）。
3. **RAGAS 官方文档《Concepts/Evaluation》**——https://docs.ragas.io/ （评估指标定义与接入方式）。
4. **《Retrieval Interactions》/《Advanced RAG》类综述**——以 "advanced RAG techniques" 检索向量数据库厂商技术博客，重点看查询改写、rerank、parent-child 检索三篇。

### 选读

- **LlamaIndex 官方文档（Advanced Retrieval）**——https://docs.llamaindex.ai/ 的 retrieval 章节，策略最全的参考手册。
- **论文《Retrieval-Augmented Generation for Large Language Models: A Survey》（2023）**——RAG 谱系全景图（Naive/Advanced/Modular RAG 分类）。
- **论文《GraphRAG: From Local to Global》（2024, Microsoft）**——了解 Graph RAG 动机与"全局问题"场景。
- **中文向**：检索 "C-MTEB 中文 Embedding 选型"、"bge/bge-m3 模型卡"（HuggingFace）了解中文场景主流选择。

### 动手实践（本周产出）

1. 用 **Spring AI 的 RAG 支持**（`VectorStore` 抽象 + pgvector 或 Redis）搭一条最小管道：解析 10 篇 Markdown → 分块入库 → 相似度检索 → 带引用回答；
2. **建立 50 条评估集**（可从你现有笔记/工单造问答对），用 RAGAS 或手写脚本跑出第一份基线报告；
3. 做一次 A/B：固定长度分块 vs 结构感知分块，用 recall 数字说话。
