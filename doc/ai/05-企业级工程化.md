# 五、企业级工程化

本文是学习路线的阶段五（贯穿全程、第 7–8 周集中攻坚）：从 demo 到生产的分水岭。五个支柱——**可观测性、评估体系、安全、可靠性、平台化**。评审一个 Agent 能否上生产，就看这五项。


## 一、可观测性（Observability）

### 1.1 三类信号

| 信号                | 在 Agent 中的内容                                                                 |
|---------------------|-----------------------------------------------------------------------------------|
| **Traces（链路）**  | 一次用户请求 = 一棵 span 树：LLM 调用、每次工具调用、检索、重试，含耗时与输入输出 |
| **Metrics（指标）** | QPS、token 用量/成本、工具错误率、P95 延迟、迭代次数分布                          |
| **Logs（日志）**    | 结构化业务日志 + 审计日志（见第三节）                                             |

### 1.2 标准与工具链

- **OpenTelemetry GenAI 语义约定**：行业标准的 span 命名与属性（`gen_ai.request.model`、`gen_ai.usage.input_tokens`、工具调用属性等），**按标准埋点，后端可随时更换**。
- **Spring AI 的 Observation 支持**：开箱即用埋点，接到 OTel 导出器。
- **Langfuse / LangSmith**：Agent 专用追踪平台——trace 树可视化、按会话回放、成本统计、在线评估挂载。自建可选 Langfuse（开源可私有化）。
- 基础设施：Jaeger/Tempo（trace 存储）、Prometheus/Grafana（指标）。

### 1.3 必看的四个看板

1. **成本看板**：按模型/租户/接口的 token 与费用；
2. **质量看板**：人工介入率、失败率、评估分数趋势；
3. **延迟看板**：端到端 P95 + 各环节拆分（模型 vs 工具 vs 检索）；
4. **异常看板**：迭代超限、工具连续失败、格式解析失败。


## 二、评估体系（Evaluation）

### 2.1 三层评估

| 层         | 对象                 | 方法                                  | 时机     |
|------------|----------------------|---------------------------------------|----------|
| **单元级** | 单次 LLM/工具/提示词 | golden set 回归、LLM-as-Judge         | 每次改动 |
| **链路级** | RAG/Agent 流程       | 端到端指标（03 册 RAGAS、任务完成率） | 每次改动 |
| **系统级** | 生产行为             | 在线 A/B、人工抽检、用户反馈回流      | 上线后   |

### 2.2 关键手段

- **Golden Dataset**：50~200 条带标准答案的用例（与 03 册共用），任何提示词/模型/分块改动都跑回归；
- **LLM-as-Judge**：用强模型按 rubric 打分（正确性/格式/语气），**先用人工标注 30 条校准 Judge**，否则 Judge 本身不可信；
- **任务完成率**：Agent 场景的北极星——给定任务，是否在预算内自主完成（含工具选择正确率、参数正确率）；
- **回归门禁**：评估接入 CI，分数低于阈值阻断合并。


## 三、安全（Security）

### 3.1 主要威胁与对策

| 威胁                 | 形式                                         | 对策                                                         |
|----------------------|----------------------------------------------|--------------------------------------------------------------|
| **Prompt Injection** | 检索文档/工具结果/网页中藏指令，诱导模型越权 | 数据与指令分槽；不可信内容包裹标注；敏感操作不听模型只听策略 |
| **越权工具调用**     | 模型被诱导调用高危工具/越权数据              | 工具级 RBAC + 租户隔离；高危工具强制 HITL 审批               |
| **数据泄漏**         | 上下文中混入他人数据/密钥外发                | 检索按权限过滤；PII 脱敏；出口内容扫描                       |
| **资源滥用**         | 死循环烧钱、恶意刷量                         | 迭代/时间/token 三级预算；限流配额                           |
| **投毒与供应链**     | 训练/检索源被污染                            | 数据来源白名单；评估集守护                                   |

### 3.2 Guardrails（护栏）实践

- **输入侧**：注入检测、敏感词/PII 识别、长度与格式校验；
- **执行侧**：工具白名单 + 参数校验（JSON Schema）+ 权限检查，**危险操作默认拒绝、白名单放行**；
- **输出侧**：引用校验（答案必须来自检索块）、事实性抽检、出口内容过滤；
- **全量审计**：会话 ID、用户、工具、参数、结果、审批人——**可回放**是合规底线。


## 四、可靠性（Reliability）

### 4.1 故障模式清单

| 故障         | 应对                                                               |
|--------------|--------------------------------------------------------------------|
| 模型超时/5xx | 超时设置、重试（指数退避）、**多模型故障切换**（主备模型自动降级） |
| 输出格式错误 | 结构校验 + 修复重试（附错误信息让模型自纠）+ 兜底话术              |
| 工具失败     | 统一异常封装回填给模型（让它换路径）、连续失败熔断                 |
| 迭代失控     | 最大迭代 + token/时间预算，超限优雅降级并说明                      |
| 流量洪峰     | 限流、队列化、并发控制（LLM 侧配额）                               |
| 成本尖刺     | 每租户配额 + 告警；缓存重复请求                                    |

### 4.2 设计原则

- **幂等**：工具调用带幂等键，重试不产生重复副作用（变更类操作尤其重要）；
- **状态落库**：对话与循环状态持久化，进程重启可恢复（02 册 HITL 的前提）；
- **降级链**：强模型失败 → 弱模型 → 规则/模板兜底 → 明确报错，永远有 Plan B；
- **缓存**：系统提示/工具定义缓存（provider 侧 prompt cache）、相同问题结果缓存（注意权限维度）。


## 五、平台化（Platform）

多团队共用一个 Agent 平台时的必备能力：

1. **多租户隔离**：配置、记忆、向量库、配额按租户隔离；
2. **配额与计费**：按租户/应用的 token 配额、用量账单；
3. **提示词/工具热更新**：配置中心下发，版本化 + 灰度 + 一键回滚；
4. **模型路由**：按任务类型路由模型（简单分类走小模型），成本与效果双优化；
5. **发布流程**：提示词与模型变更走"评估门禁 → 灰度 → 全量"，与代码发布同规范；
6. **管理后台**：会话回放、评估管理、配额调整、审计查询。


## 六、落地顺序建议

不要试图一次建成平台，按价值排序：

```
第一步（任何项目必备）：Traces + 预算/迭代限制 + 审计日志
第二步：Golden set 回归 + Guardrails（输入/执行/输出三层）
第三步：多模型降级 + 幂等与状态落库 + 成本看板
第四步（多团队时）：多租户配额、提示词热更新、模型路由
```


## 七、学习资源（阶段五）

### 必读（按顺序）

1. **OpenTelemetry GenAI 语义约定**——https://opentelemetry.io/docs/specs/semconv/gen-ai/ （埋点标准，先看 conventions 总览）。

### 动手实践（第 7–8 周产出）

1. 给 02/04 册的 Agent 接上 **Spring AI Observation → OTel → Langfuse**，能看到完整 trace 树与 token 成本；
2. 建 **golden set 回归脚本**（可挂 CI），跑出基线报告；
3. 实现 **三层 Guardrails**（注入检测 → 工具审批 → 输出引用校验）与**审计日志**；
4. 实现**多模型降级**与**预算熔断**，人为注入故障验证降级链生效。
