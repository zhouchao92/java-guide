# 七、八周学习计划

按每周 **10+ 小时**（工作日晚上 2h × 5 + 周末 4h）拆解。每周包含：学习主题、时间分配、产出物、自检问题、资源索引。**进度以"写出来的东西"衡量**，完成即勾选。

> 配套文件：01–06 册是知识正文，08 册是项目载体，09 册是资源汇总。每周资源直接对应各分册"学习资源"小节。


## 第 1 周：地基 — LLM 原理与提示词工程

**对应**：01 册 | **时间**：原理 3h、提示词 3h、Spring AI 上手 3h、整理 1h

- [ ] 学习 Attention/Token/上下文窗口/采样参数的工程含义
- [ ] 掌握结构化输出三种方式与服务端校验
- [ ] 理解 Function Calling 五步流程与"工具描述即 API 文档"
- [ ] 提示词分层结构 + few-shot/CoT/格式约束练习
- [ ] 提示词模板化与版本管理样例
- [ ] 跑通 Spring AI `ChatClient` + `BeanOutputConverter` 实验

**产出物**：结构化输出实验代码；提示词版本管理样例；上下文预算表模板（手算一次）。

**自检**：
1. 一次 Function Calling 请求里到底发生了什么？模型执行了工具吗？
2. 为什么工具调用场景必须低 temperature？
3. 你的系统提示由哪几块组成？哪块最可能被注入攻击？

**资源**（详见 01 册）：3Blue1Brown Attention 视频 → Karpathy《Intro to LLMs》→ OpenAI/Anthropic Prompt Guide → Spring AI Quickstart。


## 第 2 周：Agent Loop — 手写最小闭环

**对应**：02 册第一节~四节 | **时间**：手写 6h、范式学习 3h、测试 1h

- [ ] 用纯 Java 实现 `AgentLoop`（循环 + 终止条件 + 异常封装）
- [ ] 实现工具注册表，写好 name/description/schema
- [ ] 跑通三类用例：单工具直达 / 多步链式 / 异常恢复
- [ ] 学习 ReAct、Plan-and-Execute、Reflexion、Supervisor 范式
- [ ] 实现一个 Human-in-the-Loop 审批闸（状态落库可恢复）

**产出物**：可运行的纯 Java Agent 框架 + 三类用例测试报告。

**自检**：
1. 死循环烧钱的四道保险分别是什么？
2. 审批拒绝后，拒绝原因该怎么回填给模型？
3. 什么任务该用 workflow 而不是 agent？

**资源**（详见 02 册）：Anthropic《Building Effective Agents》→ ReAct 论文 → LangGraph Concepts。


## 第 3 周：上下文工程 + Spring AI 重写

**对应**：02 册第五节、04 册第三节 | **时间**：上下文工程 4h、Spring AI 对照 4h、文档 2h

- [ ] 给第 2 周的 Agent 加：迭代/token 预算、工具结果裁剪
- [ ] 实现简单 compaction（历史摘要压缩）
- [ ] 用 Spring AI `@Tool` + `ChatClient` 重写同一 Agent
- [ ] 写出"手写版 vs Spring AI 版"逐步映射笔记
- [ ] 观察一个真实 Coding Agent 的工具与循环行为

**产出物**：带上下文管理的 Agent；手写↔框架映射笔记（这就是面试可讲的深度材料）。

**自检**：
1. 工具返回 10 万行日志，你怎么塞进上下文？
2. compaction 压缩时，什么信息绝对不能丢？
3. Spring AI 的 Advisor 链对应手写版的哪个位置？

**资源**（详见 02/04 册）：Karpathy context engineering 分享 → Spring AI 官方文档 ChatClient/Tools 章节 → OpenCode 行为观察。


## 第 4 周：RAG 全链路与评估

**对应**：03 册 | **时间**：管道 5h、评估 4h、A/B 1h

- [ ] 文档解析 → 结构感知分块 → Embedding → pgvector 入库
- [ ] 查询管道：改写 → 混合检索 → Rerank → 带引用生成
- [ ] 建立 50 条 golden set（从你现有笔记/工单造问答对）
- [ ] 跑 RAGAS 或手写脚本，产出第一份基线评估报告
- [ ] A/B：固定分块 vs 结构感知分块，用 recall 说话

**产出物**：可评估的知识库问答原型 + 基线评估报告（数字）。

**自检**：
1. 你的场景该用 pgvector 还是 ES？理由？
2. rerank 为什么是性价比最高的提升项？
3. 检索到了仍答错，按什么顺序排查？

**资源**（详见 03 册）：LangChain RAG 教程 → Pinecone Learning Center → RAGAS 文档。


## 第 5 周：MCP 协议 + 编排概念

**对应**：04 册第一~三节 | **时间**：MCP 5h、Spring AI 3h、LangGraph 2h

- [ ] 跑通 MCP 官方 demo + MCP Inspector 调试
- [ ] 学习三大原语边界（Tools 给模型 / Resources 给应用）
- [ ] 学习传输方式、鉴权、MCP 安全清单
- [ ] Spring AI MCP Client 接入示例 Server
- [ ] 读 LangGraph Concepts，画"条件边 + checkpoint"状态机图

**产出物**：MCP 交互流程图（自己画的）；LangGraph 状态机概念图。

**自检**：
1. MCP 解决什么问题？和 Function Calling 什么关系？
2. 工具返回的内容为什么是"不可信输入"？
3. A2A 与 MCP 各管什么？

**资源**（详见 04 册）：modelcontextprotocol.io → 规范仓库 SECURITY → Spring AI MCP 章节 → LangGraph Concepts。


## 第 6 周：自研 MCP Server（项目一启动）

**对应**：04 册第六节、08 册项目一 | **时间**：Server 开发 6h、接入 3h、加固 1h

- [ ] 用 MCP SDK 封装告警/变更单查询为 Server（2–4 tools + 1–2 resources）
- [ ] 写好每个工具的 description（让模型选得准）
- [ ] Inspector 联调 → 接入 Spring AI 应用实测
- [ ] 补鉴权（Bearer/OAuth）、限流、审计日志
- [ ] 完成 08 分册项目一的 MVP 链路

**产出物**：自研 MCP Server + 接入演示；审计日志样例。

**自检**：
1. 暴露的工具里哪些必须配审批闸？
2. 审计日志要记哪几个字段才能"可回放"？
3. 租户 A 的会话能查到租户 B 的数据吗？（权限过滤在哪一层）

**资源**（详见 04/08 册）：MCP Java/Python SDK 文档 → MCP Inspector → 08 册项目一。


## 第 7 周：可观测性 + 安全护栏

**对应**：05 册第一~三节 | **时间**：可观测 5h、安全 4h、演练 1h

- [ ] 接入 Spring AI Observation → OTel → Langfuse，看到完整 trace 树
- [ ] 建成本看板（token/费用）与异常看板（迭代超限、工具错误）
- [ ] 实现三层 Guardrails：注入检测 → 工具审批 → 输出引用校验
- [ ] 建审计日志表，跑通"会话可回放"
- [ ] 对照 OWASP LLM Top 10 逐项检查自己的 Agent

**产出物**：带 trace 的 Agent + 安全自查清单（对照 OWASP 打分）。

**自检**：
1. 一次请求的 token 花在哪几个环节？（trace 里能拆出来吗）
2. 检索文档里藏了一句"忽略之前所有指令"，你的防线在哪？
3. 出口怎么防"答案与检索内容不符"？

**资源**（详见 05 册）：OTel GenAI 语义约定 → Langfuse 文档 → OWASP LLM Top 10 + MCP Top 10。


## 第 8 周：评估回归 + 可靠性 + 项目收尾

**对应**：05 册第四~六节、08 册 | **时间**：评估 3h、可靠性 4h、收尾 3h

- [ ] golden set 回归接入 CI（分数门禁）
- [ ] 实现多模型降级链 + 预算熔断，注入故障验证生效
- [ ] 关键工具幂等设计 + 状态落库恢复演练

**产出物**：CI 评估门禁 + 降级演练记录 + 完整项目（可演示、有评估数字、能讲清取舍）。

**资源**（详见 05/08 册）：Langfuse 评估功能 → Google SRE 书籍 SLI/SLO → 08 册项目验收清单。
