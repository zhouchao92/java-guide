# 一、LLM 基础与提示词工程

本文是学习路线的阶段一（第 1 周）：建立模型层地基，掌握 LLM 工作原理、结构化输出、Function Calling 机制与提示词工程，为后续 Agent 开发扫清概念障碍。


## 一、核心概念

### 1.1 Transformer 与注意力机制

- LLM 基于 Transformer 架构，核心是**自注意力机制（Self-Attention）**：每个 token 通过 Query/Key/Value 计算与上下文中所有 token 的相关度，从而"看到"全文。
- 关键直觉：模型没有数据库，只有**参数中的压缩知识 + 上下文窗口中的即时信息**。所有"记忆"和"检索"都围绕这两者展开。
- 学习目标：能向别人解释清楚 Attention 在算什么、为什么上下文窗口大小是硬约束。

### 1.2 Token、上下文窗口与计费

| 概念          | 说明                                           | 工程影响                               |
|---------------|------------------------------------------------|----------------------------------------|
| Token         | 文本的子词切分单位，中文约 1 字 = 1~2 token    | 计费、限速、上下文预算都以 token 计    |
| 上下文窗口    | 单次请求模型能处理的最大 token 数（输入+输出） | 工具结果、历史对话、文档都要"挤"进窗口 |
| 输入/输出计费 | 输入 token 与输出 token 单价通常不同           | 输出（生成）更贵，长回复要控制         |

**上下文预算意识**（企业级第一步）：给一次请求列"预算表"——系统提示 X token + 工具定义 Y + 检索文档 Z + 对话历史 W + 预留输出 N，总和不得超过窗口的安全水位（建议留 20%~30% 余量）。

### 1.3 采样参数

| 参数        | 作用                     | 典型设置                                  |
|-------------|--------------------------|-------------------------------------------|
| temperature | 分布平滑程度，越高越发散 | 事实问答/工具调用 0~0.3；创意生成 0.7~1.0 |
| top_p       | 核采样，保留累积概率前 p | 与 temperature 二选一调                   |
| max_tokens  | 输出上限                 | 防止长输出超费/超窗                       |
| stop / seed | 停止符、随机种子         | 测试复现用                                |

**企业级要点**：工具调用和结构化输出场景必须用低 temperature，否则工具参数会"幻觉"出错误值。

### 1.4 结构化输出（Structured Output）

Agent 与工具链的前提是模型输出**可被程序解析**：

1. **提示词约束**：在提示词中给出 JSON Schema 或示例，靠模型自觉遵守（最弱，需校验重试）。
2. **Function Calling 驱动**：把输出伪装成工具调用，模型生成的是受 schema 约束的参数（主流）。
3. **Constrained Decoding**：推理层在采样时屏蔽不符合 schema 的 token（最强，vLLM/Outlines 等支持）。

工程实践：无论哪种方式，**输出必须做服务端校验**（JSON Schema 校验 + 失败重试/修复），永远不要信任模型输出直接入库。

### 1.5 Function Calling 底层机制

一次工具调用的完整流程（Agent 的地基）：

```
1. 请求携带：系统提示 + 用户消息 + tools[]（工具名/描述/JSON Schema）
2. 模型返回：tool_calls（选择哪个工具 + 按 schema 生成的参数 JSON）
3. 应用执行：真实调用工具（查库/HTTP/内部系统），拿到结果字符串
4. 结果回填：以 tool 角色消息把结果放回上下文
5. 模型继续：基于结果生成最终回答，或再次发起 tool_calls → 循环
```

关键认知：
- **模型不执行任何东西**，它只"决定调用谁、传什么参数"；执行永远在应用侧。
- 工具的 **name + description 是给模型看的 API 文档**，描述写得差，模型就会选错工具——工具描述质量直接决定 Agent 准确率。
- 并行工具调用（一次返回多个 tool_calls）要作为常态设计。


## 二、提示词工程

### 2.1 提示词的分层结构

```
[系统提示] 角色、能力边界、规则、输出格式、安全约束（持久生效）
[工具定义] 工具清单与 schema（相当于 API 文档）
[对话历史] 多轮上下文（需要压缩管理）
[用户消息] 本次输入
```

系统提示的典型模块：**角色定位 → 任务流程 → 工具使用规则 → 输出格式 → 拒绝条件**。

### 2.2 常用技巧

| 技巧         | 适用场景             | 要点                                 |
|--------------|----------------------|--------------------------------------|
| Few-shot     | 分类、抽取、格式对齐 | 2~5 个高质量示例，覆盖边界情况       |
| 思维链 CoT   | 多步推理、决策       | "先分析…再决定…"；简单任务反而应关掉 |
| 输出格式约束 | 结构化返回           | 明确字段、类型、枚举值、缺省规则     |
| 角色设定     | 语气/行为稳定        | 与任务无关的角色装饰尽量少           |
| 分步指令     | 复杂任务             | 拆成编号步骤，降低跳步率             |

### 2.3 提示词版本化管理（企业级）

提示词就是代码，要走同样的工程规范：

- **与代码同库管理**：模板放资源文件/配置中心，禁止散落在业务代码字符串里。
- **版本号 + 变更记录**：每次改动记录动机与预期效果（对齐 Git 提交）。
- **模板化参数**：用占位符注入动态内容（用户资料、检索结果），**用户输入与指令分槽拼接**，防止把不可信内容放进指令槽。
- **A/B 验证**：改动先跑离线评估集（见 05 册），达标再上线。


## 三、本阶段实验（产出物）

1. **结构化输出实验**：用 Spring AI 的 `ChatClient` + `BeanOutputConverter` 让模型输出一个 Java Bean，观察自动 schema 注入与解析失败重试。
2. **Function Calling 实验**：定义 2~3 个假工具（天气、计算器），记录"工具描述写得含糊 → 模型选错工具"的案例，体会描述质量的重要性。
3. **提示词版本管理样例**：把一个提示词抽成模板文件 + 版本记录，跑同一组测试用例对比改动前后输出。


## 四、学习资源（阶段一）

### 必读（按顺序）

1. **3Blue1Brown《But what is a GPT?》**（YouTube 系列，含 Attention 视频）——建立 Attention 的几何直觉，无需推导公式。搜索 "3b1b attention" 即可。
2. **Andrej Karpathy《Intro to LLMs》**（YouTube，1 小时）——LLM 全景：预训练/微调/上下文窗口一次讲清。
3. **OpenAI 官方文档《Prompt Engineering Guide》**——https://platform.openai.com/docs/guides/prompt-engineering （技巧类第一手资料）。
4. **Anthropic 官方文档《Prompt Engineering》**——https://docs.claude.com/en/docs/build-with-claude/prompt-engineering （含长系统提示、XML 标签等实践）。

### 选读

- **《ChatGPT Prompt Engineering for Developers》**（DeepLearning.AI 短课程，免费）——面向开发者的提示词工程，含代码练习。
- **Chip Huyen《Designing Machine Learning Systems》**第 2 章（免费在线版）——理解 LLM 产品评估视角。
- **《Attention Is All You Need》**（论文）——有精力读前 6 节即可，重点是 Multi-Head 与位置编码。
- **Anthropic 提示词库**——https://github.com/anthropics/prompt-engineering-classes/ 下的 materials，大量真实案例。

### 动手实践渠道

- **Spring AI 官方文档 Quickstart**——https://docs.spring.io/spring-ai/reference/ （本栈主线，第 1 周就跑通 `ChatClient` 调用）。
- **OpenAI/Anthropic API Playground**——在线调 temperature/top_p，直观感受参数差异。
