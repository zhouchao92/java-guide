#### 什么是动态代理？

代理模式：为其他对象提供一种代理以控制对这个对象的访问（增强或拦截），分为静态代理与动态代理：

- **静态代理**：代理类在编译期手写，代理接口/实现类增多时需要为每个类编写代理，难以维护
- **动态代理**：代理类的字节码在**运行期**由程序动态生成（写入 JVM），无需为每个目标类手写代理类

两种主流实现：

|          | JDK 动态代理                       | CGLIB 动态代理                          |
|----------|------------------------------------|-----------------------------------------|
| 依赖     | JDK 自带 `java.lang.reflect.Proxy` | Spring 等内嵌的 cglib（ASM 字节码生成） |
| 生成方式 | 运行期基于接口生成 `$Proxy` 类     | 运行期生成目标类的**子类**              |

**应用场景**：

- Spring AOP：事务、日志、权限、耗时监控等横切逻辑的统一增强
- 声明式事务：`@Transactional` 对 Bean 生成代理，执行前后提交/回滚
- MyBatis：Mapper 接口无实现类，由 `MapperProxy` 动态代理执行 SQL（见 [MyBatis 源码分析](/doc/mybatis/源码分析.md)）
- RPC 框架：为接口生成客户端代理，把本地调用转为远程请求（见 [什么是 RPC](/doc/other/什么是%20rpc.md)）


#### JDK 动态代理怎么实现？

核心 API：`Proxy.newProxyInstance(ClassLoader, Class[], InvocationHandler)`，三个参数：

1. **ClassLoader**：加载动态生成的代理类
2. **接口数组**：代理类要实现的接口（决定代理对象可强转为哪些类型）
3. **InvocationHandler**：调用处理器，所有方法调用最终转发到 `invoke()`，反射调用目标对象并可前置/后置增强

```java
public class JdkProxyDemo {
    public static void main(String[] args) {
        UserService target = new UserServiceImpl();

        UserService proxy = (UserService) Proxy.newProxyInstance(
                target.getClass().getClassLoader(),
                target.getClass().getInterfaces(),
                (p, method, methodArgs) -> {
                    System.out.println("前置逻辑");
                    // 反射调用目标对象的真实方法
                    Object result = method.invoke(target, methodArgs);
                    System.out.println("后置逻辑");
                    return result;
                });

        proxy.save(); // 走 InvocationHandler#invoke
    }
}
```

执行流程：调用代理方法 → `InvocationHandler.invoke()` → `method.invoke(target)` 反射调用目标类 → 返回结果


#### CGLIB 和 JDK 动态代理的区别？

|             | JDK 动态代理                                                                              | CGLIB 动态代理                                                           |
|-------------|-------------------------------------------------------------------------------------------|--------------------------------------------------------------------------|
| 原理        | 基于**接口**，运行期生成实现该接口的 `$Proxy` 类，方法调用经 `InvocationHandler` 反射分发 | 基于**继承**，ASM 字节码框架生成目标类的子类，重写方法并增强（方法委托） |
| 实现要求    | 目标对象必须实现接口                                                                      | 目标类不能是 `final`，`final`/`private`/`static` 方法无法被重写增强      |
| 调用开销    | 每次经反射 `Method.invoke`，JDK 8+ 优化后差距缩小                                         | 子类直接调用（FastClass），调用较快                                      |
| 生成开销    | 生成字节码较快                                                                            | ASM 生成 + 加载，首次生成较慢                                            |
| Spring 默认 | Bean 实现了接口时                                                                         | Bean 未实现接口时；Spring Boot 2.x 起默认强制 CGLIB                      |

**为什么 JDK 动态代理必须基于接口？**

`Proxy` 生成的代理类已继承 `java.lang.reflect.Proxy`（`$Proxy0 extends Proxy implements XxxService`），Java 单继承，只能通过实现接口来代理目标类型——所以被代理的类型只能是接口。

**CGLIB 的局限？**

- 无法代理 `final` 类（不能被继承）与 `final` 方法（不能被重写）
- `private` 方法不参与继承、`static` 方法与父类无关，均无法增强
- 目标类最好有无参构造（子类实例化时需调用；即使无，现代 CGLIB/Objenesis 可绕过构造器实例化）
- 方法增强靠继承重写，无法增强类内部 `this.xxx()` 未代理的自调用（同类私有方法调用同样失效）
