### 什么是 IO 模型？

内核读取网络数据，先扔到 queue（socket 接收缓冲区）中再处理。IO 模型指的是用户进程以何种方式从内核获取这些数据：不同的 read() 调用方式，就对应不同的 IO 模型。


### BIO（同步阻塞 IO）

- `read()` 读取，如果没有读取到数据就阻塞，读取到数据后再返回【一个线程维护一个连接】
- 流程：`accept()` 接收连接 → 启动一个线程 → `read()` 阻塞等待数据 → 处理 → `write()` 写回
- 缺点：线程与连接一对一，连接数多时线程数线性增长，线程切换、栈内存开销大（C10K 问题）
- 适用场景：连接数少且固定的场景
- Java API：`java.net.ServerSocket`、`java.net.Socket`（Tomcat BIO 模式）


### NIO（同步非阻塞 + IO 多路复用）

- `read()` 读取，无论是否读取到数据都会立即返回，不会阻塞（没数据返回 0，需轮询）
- 三大组件：
  - **Buffer**：数据缓冲区，读写都通过 Buffer
  - **Channel**：双向通道，可读可写
  - **Selector**：多路复用器，一个线程管理多个 Channel

**多路复用器**（Linux 中 select、poll、epoll）：多个连接作为参数传递给一个函数，函数会返回其中有数据可读/可写的状态或事件。线程只需监听就绪事件，而不用逐个轮询连接。

#### select、poll、epoll 的区别

|            | select                                 | poll                            | epoll                                  |
|------------|----------------------------------------|---------------------------------|----------------------------------------|
| 数据结构   | fd_set 位图                            | pollfd 数组                     | 红黑树 + 就绪链表                      |
| fd 数量    | 有上限（默认 1024，FD_SETSIZE）        | 无硬性上限（受系统内存限制）    | 无上限                                 |
| 时间复杂度 | O(n)，每次调用需拷贝全部 fd 并全量遍历 | O(n)，同 select，但无需修改上限 | O(1)，回调机制，只返回就绪的 fd        |
| 触发方式   | 水平触发                               | 水平触发                        | 默认水平触发（LT），可设边沿触发（ET） |
| 典型应用   | 跨平台，老代码                         | 跨平台，改进 select 的 fd 上限  | Linux 高性能网络（Netty、Nginx）       |

- **水平触发（LT）**：只要缓冲区有数据就持续通知，编程简单
- **边沿触发（ET）**：仅在状态变化时通知一次，需一次读完，性能更高但编程复杂

- Java API：`java.nio.Selector`、`SocketChannel`；Netty 即基于 NIO 多路复用实现


### AIO（异步 IO）

- 发起 `read()` 后立即返回，内核从网卡读数据并拷贝到用户缓冲区，**完成后再回调通知**用户进程（NIO 需要用户自己再调一次 read 拷贝，AIO 连拷贝都由内核完成，真正异步）
- Java API：JDK 7 引入 NIO 2.0，`AsynchronousSocketChannel` + `CompletionHandler` 回调
- 平台现状：
  - Windows：IOCP，完整支持
  - Linux：网络 AIO 支持有限，实际大多由 epoll 模拟，高并发网络服务主流仍是 NIO + epoll
- 适用场景：连接数极多、读写较重（如大文件传输）的场景


### BIO、NIO、AIO 对比

|          | BIO                     | NIO                          | AIO                   |
|----------|-------------------------|------------------------------|-----------------------|
| 阻塞     | 阻塞                    | 非阻塞 + 多路复用            | 异步，回调通知        |
| 线程模型 | 一个连接一个线程        | 一个线程管理多个连接         | 一个线程管理大量连接  |
| 编程难度 | 简单                    | 较复杂（Selector、Buffer）   | 复杂（回调/异步逻辑） |
| 适用场景 | 连接数少且固定          | 连接多、短连接/长连接皆可    | 连接数极多、读写较重  |
| 典型应用 | Tomcat BIO、传统 Socket | Netty、Nginx、Redis（epoll） | Windows IOCP          |


### 阻塞与非阻塞、同步与异步的区别

- **阻塞 vs 非阻塞**：关注**调用 read() 时进程状态**——阻塞：没数据就挂起等待；非阻塞：没数据立即返回 0
- **同步 vs 异步**：关注**谁完成数据拷贝**——同步：用户线程自己从内核拷贝到用户空间；异步：内核拷贝完成后主动回调通知
- 组合：BIO = 阻塞 + 同步；NIO = 非阻塞 + 同步（多路复用仍需用户自己 read）；AIO = 异步
